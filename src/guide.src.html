User guide

Test Development in FideV2

The Test Development module is where the tasks for the fide exams are created. A test developer assigns a module, an item writer writes it, the test developer reviews it, translators create the other two language versions, and the finished module goes into a test version.

This guide walks through the steps for each role, briefly. If you are stuck, start with Troubleshooting, or search with the field above (/ or Ctrl K).

The interface can be shown in English, German, French or Italian. This guide quotes the English labels, e.g. Submit for review.

1 · Basics

Signing in and Home

Everyone
  1. Open the application address. You are taken to the FIDE sign-in page (Keycloak).
  2. Enter your e-mail address and password. Your administrator gives you a password; ask them if you forget it.
  3. After signing in you land on the page for your role: My tasks for item writers, My translations for translators, Task bank for test developers.

Home shows quick actions and the workspaces you can use. Test developers also see a Waiting for your review card when a task needs their decision.

A menu item is missing, or you see "Unauthorized"?

The menu follows your permissions. Ask your administrator to add you to the right group (ItemWriter, Translator or TestDeveloper). The change applies the next time you sign in.

The life of a task

Everyone

The editors show this seven-step bar at the top, with the current step highlighted. Below it, Next step tells you what to do.

2. ReviewReviewer decidesTest dev
3. TranslationInto the other 2 languagesTranslator
4. Translation reviewLanguages comparedTest dev
5. TrialTried out in a test versionTest dev
6. Final reviewFinal decisionTest dev
7. ReleasedReleased–

The most important rules

  • Saving is not submitting. Save draft only saves your work. The task moves on only with a Submit… button.
  • Locked after submitting. You can only edit it again if it is sent back to you.
  • From translation on, the whole module moves together. When every translation of a module is done, the whole module goes to translation review at once; Ready for Trial, testing and the final decision also apply to the whole module.
  • A pending scenario proposal blocks the module. Until it is decided, no task of the module can be submitted.

Every status is explained briefly in Statuses.

2 · For item writers

My to-dos and My tasks

Item writerTranslator

My to-dos shows everything waiting for you in one place: writing, revising and translating.

To writeAssigned to you, not handed in yet.Write
To translateLanguage versions assigned to you for translation.Translate

My tasks

A more detailed list of your writing tasks, with filters and a column picker. Tabs: All, Needs revision, Not started, In progress. The row button: Start (not touched yet), Continue (draft), Revise (sent back).

Clearing a draft

For a task in Draft, Clear draft content in the row menu deletes every field. This cannot be undone.

You also get an e-mail about a new assignment (if e-mail notifications are on for you). The link in the e-mail takes you straight to the task.

The task editor

Item writer

From top to bottom

  1. Lifecycle and Next step: where the task is and what you need to do.
  2. Domain / Action field / Scenario card with Instructions below it: the topic of the module and the test developer's notes for you. Read them before you start. If the scenario does not fit, see Proposing a scenario change.
  3. Tasks in this module: if you have several tasks in the module, switch between them here (with their status). Switching saves automatically.
  4. The form: the fields of the task type, in the order of the task structure.
  5. Sticky bar at the bottom: Save draft and Submit for review, with the number of incomplete fields.
Unsaved changes

If you try to leave without saving, you get a warning (Unsaved changes). Leave without saving discards your changes; Cancel takes you back to the editor.

Filling in the fields

Item writerTranslator

The task type sets the order and number of fields; you cannot change them. Fields marked with a star are required.

FieldWhat goes in
Situation descriptionA short description of the situation.
Context imageAn image for the situation. Without one, a placeholder image is used.
Instruction / Instruction input / IntroductionInstructions and introductory text. If several instructions are needed, fill in all of them.
Input textThe main text of the task (formatted), with an optional title and salutation.
Items / Item groupQuestions and answers with a title. Can include an example item (E) and alternatives.
Multiple-choice itemsMultiple-choice items with options.

Items, examples, alternatives

  • Add item adds an item to the field; Add example item adds an example (marked E).
  • Alternative: write another version of the same item. Exactly one per group is the Preferred alternative; only that one goes into the export.
  • Clicking an item number opens a menu for managing the numbering.

Images and audio

  • For images, Browse searches the images already uploaded, by file name. Click to select, double-click to use straight away. Upload a new one with Upload new image (.jpg, .png).
  • For audio, upload an .mp3, or give a transcript instead.
Word count

Some fields watch the word count (e.g. 180–200 words) and warn you when you are outside the range. It is only a warning; it does not block submitting.

Answer key

Item writerTest developer

For reading and listening tasks, every item (except examples) needs a correct answer.

  1. Click the key icon next to the item.
  2. For a text answer, fill in Correct Answer and, if needed, answers that count as wrong (Incorrect Answer). For multiple choice, select the correct option.
  3. Set the points (Max. points, more than 0), then Save.
  • Task types without an answer key (e.g. open-answer tasks) show no key icon.
  • If an answer is missing when you submit, you get a warning: Go to Answer Key (fill it in) or Proceed anyway (submit as is). It is better to fill it in.
  • During review the key is read-only (View answer).

Saving and submitting for review

Item writer
  1. At any time: Save draft. The task becomes Draft; only you see the change.
  2. If the bar says "N required field(s) still incomplete", click Show me: it jumps to the first missing field and lists the others by name.
  3. When everything is complete: Submit for review.
  4. In the confirmation dialog the reviewer is usually selected automatically (★, locked field). If not, pick one from the list.
  5. Submit. The task moves to Task Review, the reviewer gets an e-mail, and you see it under Waiting for review.

Revisions and comments

Item writer

If the reviewer sends the task back (Task Revision), it appears in your list with a Revise button.

  1. The Changes requested by the reviewer bar at the top of the editor shows how many comments there are and on how many fields.
  2. Go to first comment: jumps to and opens the first open comment. Fields with comments have an orange speech bubble with the number of open comments.
  3. Fix the field, then click Mark resolved on the comment. The bar shows how many are still open ("X of Y still open").
  4. When you are done: Submit for review.

You can also reply to a comment: type in the box and click Post comment. Tasks that are assigned but not started yet (Assigned) have no comments.

Proposing a scenario change

Item writer

If the module's scenario does not fit the task, you can propose another one. The test developer decides.

  1. In the editor, click Propose Scenario Change.
  2. Choose an existing scenario from the catalogue (Select Existing Scenario) or describe a new one in your language (Create New Scenario, 10–500 characters). Then Send proposal.
  3. Until it is decided you can keep writing and saving, but you cannot submit (Submitting is blocked until the scenario proposal is decided).
  4. If approved, the module switches to the new scenario automatically. If rejected, the editor shows the reason, and you can propose again.
3 · For translators

My translations

Translator

A translation appears for you when the reviewer approves the source-language task and selects you as translator.

The To translate group in My to-dos or the My translations list shows the task groups to translate. The German/French/Italian columns show which language is done (Done), in progress (In progress), to translate (To translate) or not available yet.

Currently no e-mail is sent when translation tasks are created. Check your list regularly, or ask the test developer to let you know.

The multi-language editor

TranslatorTest developer

The language versions are shown in panels side by side, so you see the source text and your translation together.

Panel headerMeaning
You are editingYou are editing this language.
Read-only · Assigned to: NameSomeone else is working on it, or its status cannot be edited.
Source textThe original, source-language version. You translate from it; it cannot be changed.
  • Use the language toggles to hide or show panels. The current task is always visible.
  • Show tasks side by side puts the tasks of the module next to each other.
  • Stop editing switches your own panel to read-only view (e.g. to compare); Edit switches it back.
  • Switching language or task saves automatically.

Translating and submitting

Translator
  1. Open the task (Translate).
  2. The translation already has the item structure (numbering, example marks, alternatives) and the images, but the texts are empty. Fill in the You are editing panel.
  3. Save as you go (Save draft); the status becomes Draft Translation.
  4. When done: Submit translation at the bottom of the panel, and confirm. The status becomes Translation Completed.

If you translate two languages, the page stays open after you submit one, and the unsaved text in the other panel is kept.

Why is it still waiting?

Translation review starts when every language of every task in the module is done. Until then your submitted translation waits in Translation Completed.

If it is sent back

The reviewer can send back a translation per language (Translation Revision). It then appears in your to-dos again; fix it based on the comments and submit it again.

Assigning a new module

Test developer

Task bank → Assign a new module (or Ctrl K → "assign"). The form has five numbered steps with a live summary below.

  1. Source language: the language the task is written in. The other two are created later, for translation.
  2. What to create: test kind → skill → module or single task. Reading and Writing creates a whole module; Speaking and Listening Comprehension create a single task.
  3. Scenario: Domain → Action field → Scenario from the catalogue. If it is missing, add it to the catalogue first.
  4. Assign to: only item writers who speak the source language are listed.
  5. Instructions: notes for the item writer, shown above the task. Required.

Check the Review before assigning summary, then Create & assign. The item writer gets an e-mail, and the tasks appear for them as Assigned. The deadline is 14 days from the assignment.

You can assign the same module number (e.g. module2) several times with different scenarios. The test version wizard chooses between them step by step.

Reviewing and deciding

Test developer
  1. Open the task from the Waiting for me tab (or Open next task).
  2. Check the content. Where something needs fixing, add a comment to the field: the speech bubble icon next to the field → Add Comment → text → Post comment.
  3. Choose a decision in the Your decision panel. Going back is on the left, moving forward on the right; each card describes what happens.
  4. Check the assignees in the confirmation dialog, then Confirm change.
StatusDecisionWhat the confirmation asks for
Task ReviewSend back for revisionThe item writer (preselected). Your comments go with it.
Task ReviewApprove and send to translationOne translator for each of the other two languages (list filtered by language pair).
Translation ReviewRequest translation changesWhich languages need revision, and who translates them. Unselected languages stay unchanged.
Translation ReviewApprove and mark ready for trialThe reviewer. The whole module becomes Ready for Trial, so this only works when every task of the module is in translation review.

After a decision you return to the Waiting for me tab, so the next task is one click away.

Editing someone else's task

As a test developer you can edit any task. If the task is not assigned to you, you must give a modification reason when saving (Content Update, Error Correction, Language Improvement, Structure Change, Other) and a short description. This goes into the change history.

Changing the scenario

For an assigned module you can change the domain, action field and scenario directly with the pencil next to the scenario in the multi-language editor.

Change history

Test developer

Expand the Change history bar at the bottom of the multi-language editor to see the history of the task group: status changes, assignee changes and content changes, with language and modification reason. View changes opens the comparison: the old and new version side by side, with the changed fields highlighted. Next change scrolls to the next difference.

Deciding on scenario proposals

Test developer

A pending proposal blocks the module, so decide quickly. A badge in the sidebar counts pending proposals.

  1. Scenario proposals → Pending tab → Review.
  2. Approve: enter the scenario text in the two missing languages (at least 10 characters each; you can also correct the proposer's language), then Approve. The new scenario is added to the catalogue and the module switches to it.
  3. Reject: Reject Proposal; a reason is required. The item writer sees the reason in the editor.

Scenario catalogue

Test developerEveryone can read

Domains, action fields and scenarios in all three languages, in a searchable table. As a test developer you can add new entries: Add new domain, Add new action field (under a domain), Add new scenario (under an action field). The name is required in all three languages.

Entries cannot be edited or deleted in the interface once added. If you make a typo, contact the administrator.

Test versions and export

Test developer

You build a test version for the trial from Ready for Trial modules.

  1. Test versions → Create TestVersion.
  2. Choose the variant (Normal, Erprobung, Modell, Schulung), the test kind and the skill, then the level, and enter the version number. The available levels depend on these choices; if the list is empty, change the choices above.
  3. The wizard asks for one module number per step. Select exactly one module instance; expand a row to see its tasks.
  4. If there is no suitable module: Create module. The assignment form opens prefilled, and afterwards you come back to the same step.
  5. Moving between steps saves automatically. At the end: Finish.

A module added to a test version moves to In Testing; if you remove it, it goes back to Ready for Trial.

Export

Use Export on a row to download a ZIP per language. It contains export.csv (one header row and one data row, separated by semicolons) and the referenced images. Only preferred alternatives are included.

5 · If you are stuck

Troubleshooting

Everyone

Click a question to see the answer. The search above also searches the answers.

The submit button is disabled
  • A required field is missing: check the number in the bar and click Show me.
  • The module has a pending scenario proposal: wait for the test developer's decision.
  • The task is no longer with you (e.g. you submitted it for review): the editor is read-only.
"This task is not available to you"

The task has moved on in the workflow or was assigned to someone else. Your current work is listed under My to-dos.

No reviewer can be selected when submitting

If the reviewer field is empty, pick someone from the list. If the list is empty too, no test developer speaks that language. Contact the module's test developer or the administrator (the user's spoken languages need to be set).

"Missing solution key" warning when submitting

Some items have no correct answer. Go to Answer Key → fill them in at the key icons. If the task type has no answer key editor, the warning says so, and Proceed anyway is the right choice.

Did I lose my work?

Switching task or language saves automatically. When you leave with unsaved changes you get a warning. If you chose "Leave without saving", the unsaved part is gone; your last saved draft is kept.

I did not get an e-mail
  • Check your spam folder.
  • The administrator may have turned off e-mail notifications in your profile.
  • No e-mail is sent when translation tasks are created, or when a draft is saved.
  • There is currently no reminder about approaching deadlines.
I submitted my translation, but it does not go to review

Translation review only starts when every language of every task in the module is done. Until then it waits in Translation Completed. You have nothing to do.

The panel of my language is "Read-only"

The header shows who has the task. If it should be with you, ask the test developer to assign it to you in the task bank (Change assignee).

"Approve and mark ready for trial" gives an error

This step applies to the whole module. It only works when every language of every task in the module is in Translation Review. If a language is still being revised, wait for it.

I cannot add a module to a test version
  • The module has the wrong status (it must be Ready for Trial).
  • The module's level, test kind or skill does not match the test version.
  • The module has a pending scenario proposal.
Archiving or releasing fails

Known limitation: the release step (Release task) currently gives an error, so neither modules nor test versions become "Released", and so they cannot be archived either. From final review, only discarding (Discard task) works at the moment, for the whole module. A fix is in progress; until then leave the module in Final Review.

I assigned the wrong item writer or the wrong scenario
  • Wrong item writer: Change assignee on the task row.
  • Wrong scenario: the pencil next to the scenario in the multi-language editor.
  • Completely wrong assignment: while nobody has started it, Cancel assignment in the task bank side panel.
I cannot find the translator in the list

Only users with translator permission and the right language pair (source language → target language) are listed. The administrator sets the language pairs on the user's profile.

I cannot see a menu item / "Unauthorized"

The menu follows your group membership. Ask the administrator to add you to the right group, then sign out and in again.

The task bank loads slowly, or "The modules could not be loaded"

With many modules, loading can take a few seconds. If you see the error, click the retry button; if it keeps failing, the server is probably restarting, so try again in a few minutes.

Module status

The module status is calculated from its tasks: Assigned (nothing started), In Progress (writing, review), In Translation (any task in translation), then Ready for Trial, In Testing, Final Review, Released / Discarded / Archived once every task has reached that point.
